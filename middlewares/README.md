# Middlewares

## 가이드라인

- 단일 역할: 하나의 Middleware는 하나의 책임(예: 인증, 로깅, 에러 핸들링 등)만 수행하도록 작성합니다.
- 순서 고려: 여러 Middleware가 연속적으로 적용될 때 실행 순서를 명확하게 정의하고, 의존성이 있는 경우 주석 등을 통해 기록합니다.
- 에러 전파: 에러 발생 시 next(error)를 호출하여 글로벌 에러 핸들러로 에러를 전달합니다.
  - CreateError 함수를 통해 오류를 생성 후 catch 문으로 전달하여 next(err) 호출 방식을 채용할 수 있습니다.
    - EX) throw CreateError(401, '~~ 오류');
- 최소한의 상태 유지: 가능하면 전역 상태를 수정하지 않고, 요청(req) 혹은 응답(res)에 한정된 처리를 합니다.
- 비즈니스로직 상 필요한 값은 req 에 담아서 ctrl, svc 에 전달할 수 있습니다.
  - EX) chkToken.js
