# Validators

## 가이드라인

- 입력 검증 집중: API 요청 시 입력값의 유효성 검사 로직은 Validator 계층에 집중시켜, Controller나 Service에서는 검증 로직을 제외합니다.
- 재사용성: 공통 검증 로직(예: 이메일, 전화번호 등)은 별도 함수나 모듈로 분리하여 여러 곳에서 재사용합니다.
- 명확한 에러 메시지: 검증 실패 시 반환할 에러 메시지와 상태 코드를 명확하게 정의하고, 클라이언트에 필요한 정보를 제공합니다.
- 규칙 확장 용이성: 새로운 검증 로직 추가 시 기존 규칙과 쉽게 통합할 수 있도록, 확장 가능한 구조로 작성합니다.

## common

- Optional 한 입력값은 Opt~~.js 내 파일을 참고하면됩니다.
- Required 한 입력값은 Required~~.js 내 파일을 참고하면됩니다.
