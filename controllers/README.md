# controllers

## 가이드라인

- 역할 분리: 비즈니스 로직은 최대한 Service 계층으로 위임하고, Controller는 요청/응답의 흐름 제어에 집중합니다.
- 명확한 책임: 하나의 Controller 파일은 하나의 리소스 혹은 엔드포인트 그룹에 대한 책임만 갖도록 구성합니다.
- 에러 처리: try-catch 블록을 사용해 발생할 수 있는 에러를 잡고, 적절한 HTTP 응답 코드와 함께 클라이언트에 반환합니다.
  - 현재 하이패스는 성공 시, 200 만 사용중
  - 입력값 유효성 검사를 통한 오류는 400 에러 만 사용중
- 미들웨어 연계: 인증, 권한 등 사전 처리가 필요한 로직은 Controller 내부가 아닌 Middleware를 통해 처리합니다.
- 코드 가독성: 각 함수는 단일 책임 원칙(SRP)을 준수하고, 필요한 경우 별도의 헬퍼 함수로 분리합니다.
